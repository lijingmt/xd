# 逻辑新区架构十遍审计记录

审计日期：2026-08-01。范围包括逻辑区配置、身份、视觉、战斗、社交、经济、
登录、HTTP、多线程、部署和管理后台。本记录区分“已修复漏洞”和“明确的架构边界”，
避免把共享单进程能力误称为完全独立世界。

## 第一遍：配置与宿主机权限

- 已修复：`restart-docker.sh` 最终把 `etc` 重新设为 `777`，逻辑区开关可被非预期
  容器用户改写。现在目录为 `755`、文件为 `644`。
- 已修复：配置文件没有数量和体积上限。现在最多 99 个 `.conf`、单文件 8192 字节，
  且只接受普通文件。
- 保持：任一文件非法时拒绝整份候选快照，不发布半状态。

## 第二遍：热加载与多线程

- 通过：候选 mapping 构建完毕后一次替换，发布后不原地修改；热点读取不抢全局锁。
- 已修复：邮件、帮派审批、家园商店、赠送、交易子命令和管理命令只拿单账号锁，
  可能并发写同一离线档案或物品。现在这些领域前缀统一进入 HTTP 核心锁。
- 已修复：同步更新 `_http_api_mod` 与旧 `single/d/http_api` 镜像，测试禁止双目录漂移。

## 第三遍：身份和管理员旁路

- 已修复：空账号 ID 原先默认允许交互；账号级策略现在缺失身份即失败关闭。
- 已修复：原先只要目标是管理员，普通玩家就能反向穿透可见性。现在管理员旁路有方向：
  管理员主动查看/操作可跨区；普通玩家仅可通过 `chat`、`mail` 联系跨区客服。
- 已修复：名字为空的畸形玩家对象不再被当成共享系统对象。

## 第四遍：可见性与信息披露

- 通过：房间、移动、在线列表、人物详情、HTTP room/target/battle 均由服务端过滤。
- 已修复：公共 `/api/partitions` 不再暴露 cluster、revision、配置文件错误详情；只返回
  登录必需字段和健康摘要。
- 已抽象：聊天、战斗、队伍、帮派、邮件、交易、拍卖、家园、榜单、掉落等能力使用
  固定能力矩阵，未知能力失败关闭。

## 第五遍：战斗、NPC 与召唤

- 已修复：自动挂机会把其他区已经交战的 NPC 计为可见目标，随后反复选中又被战斗层
  拒绝。候选统计和最终选怪现在都走 `combat` 能力。
- 已修复：召唤物聚焦和龟灵嘲讽增加实时战斗策略门。
- 已修复：配置切分后的极短清理窗口内，群疗、山河壁和助手队友判断仍可能沿用旧队号；
  每次生效前现重新检查 `team` 能力。

## 第六遍：组队、帮派与社交状态

- 通过：组队邀请、接受、聊天、战利品和热切分清理均有边界检查。
- 已修复：NPC 团队经验、金币、任务物品按旧 `termMain` 分配时可能跨区；奖励接收者
  现在必须与击杀归属账号仍处于同一交互组。
- 已修复：拆区后旧帮派成员虽然在界面不可见，仍可伪造直接命令修改共享公告、职级或
  解散帮派。管理命令和 BANGD 最终写接口现在双重校验帮主归属组。

## 第七遍：经济、拍卖、家园与掉落

- 已修复：掉落的 `item_whoCanGet` 在 120 秒后会变成 `1`，导致区归属丢失。
  新增独立的 `item_logical_zone_owner`，保护过期仍不能跨区看见或拾取。
- 已修复：直接执行 `get` 不再绕过房间渲染过滤。
- 通过：拍卖列表与最终结算、家园购买与店主入账、交易、赠送都在最终写入前复查策略。

## 第八遍：登录、HTTP 与旧维护入口

- 已修复：`login_monst`、`login_fee`、`login_fee_xd` 可绕过逻辑区登录开关。
- 已修复：`login_fee_xd` 使用固定 `none` 且无认证。两个维护登录入口现在都要求至少
  24 字符的 `XIAND_MAINTENANCE_TOKEN`；未配置默认拒绝，参数调试日志已移除。
- 通过：Vue、旧 socket、注册、找回/绑定相关登录链均调用服务端区策略。

## 第九遍：管理性抽象与后台

- 新增：`capabilities.pike` 统一领域策略；旧 `can_interact` 只作为兼容门面。
- 新增：`management.pike` 统一管理后台写入，复用正式 parser，具备 admin 权限、
  revision 冲突检查、`.bak`、临时文件 rename、完整快照失败回滚和审计日志。
- 新增：管理员房间“逻辑新区管理”，支持创建、开放、关闭、下架、隔离、合区、修改和
  上一版回滚。新区默认关闭登录与注册；合区先隔离、再换 cluster、最后互通。
- 新增：`scripts/logical-zone-admin.sh` 提供相同的安全运维流程，方便容器宿主机操作。

## 第十遍：测试、重启与可观测性

- 管理脚本完成临时目录中的创建、开放、合区和列表测试。
- 第一次真实重启发现 HTTP 线程管理双目录漂移，测试按预期失败；同步后再次完整重启。
- 最终 TestUnit：`passed=35 failed=0 skipped=4`。
- 游戏端口 `13800`、HTTP 端口 `8888` 均监听；公开区列表仅显示 `xd01`，健康为正常。
- 最终日志未发现语法、编译、未定义符号、非法 cast 或 TestUnit 失败。

## 仍需明确的架构边界

当前实现已经做到玩家视觉、玩家交互、掉落和主要经济路径隔离，但仍是一套共享进程、
共享地图模板和共享普通 NPC 刷新池：

- 一个区占用某只共享 NPC 时，其他区不会看见它，但会间接感受到刷新资源被占用。
- 城池归属、部分全服活动和公共资源产能仍是全进程状态，不是每区独立副本。
- 所有逻辑区仍共享单进程故障域和容量上限。

如果产品定义要求“连 NPC 数量、城池、活动进度和资源产能都完全独立”，下一阶段应在
现有能力网关下面增加 `world instance adapter`：按 `query_user_group()` 克隆房间状态，
并让 CITYD、活动 daemon 和资源刷新 mapping 以 group 为第一维。不要继续在业务命令中
散加区号判断；那会重新产生不可审计的旁路。
