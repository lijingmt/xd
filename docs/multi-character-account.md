# 注册账号多人物档案

## 目标

同一个注册账号最多建立 10 个职业人物，每个职业一个档案。人物的等级、技能、已穿装备、背包、个人仓库、任务、社交与家园数据继续保存在各自原有的 `data_xiand/u/<末两位>/<人物ID>.o` 中，不共享成长数据。玩家可主动把个人仓库物品转入独立的账号共享宝库，让同一注册账号下的其他人物领取。新版现金充值余额和累计充值权益属于注册账号；旧人物已有玉石及任务、活动、掉落奖励仍属于具体人物。

## 老账号兼容

- 没有账号索引的老账号不迁移、不改名、不改存档路径；原账号人物就是默认人物。
- 仅登录或查询老账号不会创建新文件。第一次新增第二个人物时，才写入 `data_xiand/accounts/<末两位>/<账号ID>.json`。
- 旧 Socket/JSP 登录、旧 Vue TXD 链接、自动浏览器链接仍可使用具体人物 ID 和原密码直接登录。
- 只有一个人物的老账号经新版账号登录后仍自动进入游戏，不额外打断玩家。
- 新人物是标准 `GAMELIB_USER` 档案；首次进入调用原有 `choice_profe`，因此职业初始技能、装备、药品、新手引导和注册统计仍只有一套实现。
- 同一个注册账号可以有多个不同职业人物同时在线。HTTP/Vue、Socket/JSP、直接 TXD 和自动浏览器入口都走同一账号锁；默认上限为 5。相同人物 ID 仍永远只允许一个玩家对象，避免两个对象并发覆盖同一份 `.o` 存档。

## 文件与恢复

账号索引采用独立 JSON 文件，写入流程为临时文件、尺寸校验、旧文件备份、原子替换。主文件无效时会读取 `.bak`；主文件和备份都无效时失败关闭，禁止把已有多人物账号误判成老单人物账号。

新人物建立顺序：

1. 校验账号、人物上限、阵营职业组合和重复职业。
   如果已有尚未完成职业初始化的人物，必须先进入该人物完成创建，不能连续占用空白档案。
2. 使用密码相同、ID 不冲突的新标准人物档案落盘。
3. 原子更新账号索引。
4. 索引失败时只回滚本次新建的人物档案。

`data_xiand` 已是 Docker 的持久化挂载目录，因此 `accounts` 会与玩家档案一起跨镜像和容器重建保存，不需要新增卷。备份时必须同时备份 `data_xiand/u` 与 `data_xiand/accounts`，后者包含人物索引、共享宝库和共享充值钱包文件。

## 注册账号共享充值钱包

- 从管理平台选择注册账号或其任一职业人物充值，最终都解析到同一个注册账号，写入 `data_xiand/accounts/<末两位>/<注册账号>.wallet.json`。人物 ID 只决定精金宝箱、火月签等附赠物发给谁，不决定充值余额归属。
- 一元充值沿用旧规则折算为 10 碎玉价值。人物管理页明确显示“注册账号共享充值余额”，避免把同一余额误解成每个职业各有一份。
- 旧人物背包中的玉石不迁移；任务、活动、反馈奖励、掉落和跨游戏兑换继续发给当前人物。购买时先消耗当前人物玉石，不足部分才从共享充值钱包扣除。
- 钱包在独立互斥锁内串行入账、消费和退款。同账号多个职业同时消费时共享同一个持久化余额，不会分别复制余额。每次变动生成事务流水、修订号和扣款后余额，流水最多保留 200 条，文件与内存缓存均有上限。
- 管理员充值要求管理员权限和第二次确认。确认链接含随机请求编号并在 30 分钟后失效；同一链接重复提交只返回第一次结果，不会重复入账或重复发放附赠物，请求编号与人物、金额或管理员冲突时失败关闭。账号短时确认记录最多 256 条，达到上限会拒绝新入账而不是丢弃尚有效的防重记录。
- 钱包使用临时文件、尺寸校验、旧主文件备份和原子替换。余额文件损坏时禁止入账和使用共享余额，也不会从可能早于某次消费的 `.bak` 自动恢复；人物本身仍可登录，管理员修复权威主文件后恢复使用。
- 第一次新版充值时，以账号下人物已有累计充值值的最大值作为兼容基线，再增加本次金额；以后由钱包记录账号累计值。在线兄弟人物立即同步，离线人物下次登录对账，因此充值经验倍数等累计权益保持一致。
- 旧 `yushi_add_fee` 客户端命令已经封闭，只保留管理员维护兼容；正式管理充值统一走共享钱包。历史数据不批量迁移，不会因部署新版而改写旧人物背包或存档。

## 账号共享宝库

- 旧个人仓库结构和容量规则保持不变；共享宝库是额外入口，不会让旧代码突然读到其他人物的物品。
- 第一次成功存入时才创建 `data_xiand/accounts/<末两位>/<注册账号>.storage.json`，基础容量 20 格，当前硬上限 500 格。
- 个人仓库旧物品在首次查看共享宝库时会获得永久的 64 位十六进制物品 ID。仅补 ID 不会创建共享文件；人物档案必须保存成功后才允许转移。
- 存入和取出都直接在“个人仓库 ↔ 共享宝库”之间完成，不经过背包，避免背包满、自动拾取和同名装备造成歧义。按钮传递永久 ID，而不是物品名称、路径或数组位置。
- 每次操作先把物品写入持久化 pending/托管记录，再移除来源并保存人物，最后提交目标位置。同一请求重复点击不会把另一个同名装备误当成原装备。
- 重启或中断后，系统通过永久 ID 检查物理人物 `.o`，确定提交还是回滚；共享和个人位置总计只能存在一份。
- 共享主文件是唯一权威。主文件缺失或损坏但仍有 `.bak`/`.tmp` 时会失败关闭，不能自动启用可能过期的共享备份，否则已取出的装备可能被复活。
- 如果管理员恢复了旧人物 `.o.bak`，登录时会在人物注册上线前对账：共享宝库已有相同 ID 时，自动移除个人仓库里复活的旧副本并保存。

游戏中从个人仓库页进入“账号共享宝库”，可查看两个仓库并按永久 ID 存入或取出。所有共享操作均再次校验人物确实属于当前注册账号。

## 接口

- `POST /api/account/login`：验证注册账号并签发 12 小时随机账号令牌。
- `POST /api/account/characters`：读取令牌所属账号的人物摘要及共享充值余额；令牌只放请求体，不进入 URL、访问日志或浏览器历史。
- `POST /api/account/characters/create`：建立一个尚未拥有的职业人物。
- `POST /api/account/characters/select`：校验归属后返回该人物的旧格式 TXD，并安全保存、退出同账号的其他 Vue 人物。
- `POST /api/account/logout`：撤销账号令牌。

账号令牌只允许人物管理，不能执行游戏命令；游戏仍使用具体人物 TXD。人物选择以服务端账号归属校验为准，前端传入其他人物 ID 无法越权。

## 密码规则

游戏入口的“修改密码”、管理员密码修改和旧手机安全码找回入口都保持账号级语义：先保存在线人物，为全部人物准备密码临时文件，全部准备成功后再原子替换，并同步在线对象、刷新恢复备份、清理 HTTP 密码缓存、撤销旧账号令牌。任何可自动恢复的 `.bak` 都不会保留仍可登录的旧密码。单人物老账号走同一入口但行为与原来一致。

账号管理令牌为 64 位随机值，12 小时滑动过期；单账号最多保留 8 个并发管理会话，全服总量有界。令牌只存于浏览器 `sessionStorage`，关闭该标签页后不会长期驻留；所有游戏 JSON 响应均禁止缓存。

## 可配置多人物在线与并发

配置文件为 `gamelib/etc/account_characters.conf`：

```text
max_online_characters=5
```

允许范围为 1-10，文件缺失、数值越界或格式非法时安全回退到 1。配置会在每次人物登录时读取，并由 daemon 每 15 秒检查一次；因此发现运营或并发风险时可直接改成 `1`，无需修改代码或重启 Pike，已有超额人物也会先保存再按登录顺序清退。选择人物接口不会再无条件踢掉其他职业。

HTTP 游戏命令锁按注册账号归一，而不是按具体人物 ID。多个兄弟人物可以保持在线，但同账号 HTTP 命令、共享宝库存取和登录切换仍串行，避免账号资源竞态；共享充值钱包另外使用账号钱包互斥锁，覆盖管理员和旧 Socket 路径的并发消费。HTTP 首条命令必须回到 Pike 主循环完成玩家创建，避免工作线程与 Socket 世界对象注册并发。相同人物重新登录，或超过配置上限时，系统会先验证保存，再同步清理活动对象、HTTP 虚拟连接和旧 Socket 连接。

同一人物从 Vue/HTTP 界面切换到旧 Socket 界面时也会先在账号锁内执行可验证保存；保存失败会拒绝切换，禁止直接销毁对象后从旧存档重建。

## 共享充值十轮审查记录

1. 老账号兼容：只读余额为零且不创建钱包文件，旧 `.o` 和人物玉石不迁移。
2. 持久化恢复：主文件原子替换；损坏主文件即使存在有效旧备份也停止余额操作，修复权威主文件后恢复。
3. 权限与隐私：普通人物不能调用管理充值或旧铸币命令；账号令牌和充值确认编号不进入 URL 或普通日志。
4. 并发与因果：两个职业并发扣同一余额只能成功一次；重复、冲突和过期确认均不会再次入账。
5. 职业完整性：充值只改变账号钱包与累计权益，不触碰人物职业、技能、装备、任务和新手流程。
6. 独立与共享边界：旧玉石及免费奖励留在人物，现金余额共享；购买按人物玉石优先、共享余额补差结算。
7. Vue 与设备体验：人物中心显示共享余额和边界说明，手机改为两行紧凑布局；源文件、`dist` 和部署目录一致。
8. 密码与恢复：钱包不保存密码；既有账号级密码原子同步、缓存失效和恢复测试继续通过。
9. 分区与部署：钱包跟随注册账号区号，保存在现有 `data_xiand/accounts` 持久卷，不需要镜像种子或新增挂载。
10. 发布卫生：静态审计、Vue 测试/构建、Pike 真重启、51 个 TestUnit、HTTP 200/405/401 边界、无测试残留和差异检查全部通过。
