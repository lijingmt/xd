# 山海万灵 V2 十轮独立审查

日期：2026-08-02

分支：`feature-pet-evolution-pvp`

## 审查结论

山海万灵 V2 已按十个独立维度完成反查。宠物专测为 44/44，整库 TestUnit 为 51 套通过、0 套失败、4 个辅助脚本跳过；Vue 三组测试和正式构建通过，游戏端口 13800 与 HTTP 端口 8888 正常。最新游戏介绍 PDF 共 8 页，已完成文本抽取和逐页渲染检查。

## 第一轮：V1 旧档与原子迁移

- 永久格式从 V1 升级为 V2；旧宠物只在内存补为一星，单纯查看不会批量改写磁盘。
- V1 迁移前仍按旧版 30 级上限校验，伪造的高等级旧档不能借新版 60 级上限通过。
- 下一次真实培养、领奖或材料变更才通过原子保存自然落为 V2；临时迁移标志不会写入文件或返回客户端。
- 版本、账号、宠物唯一 ID、物种唯一性、等级、星级、羁绊、材料、人物分配和奖励会话继续严格校验；坏档失败关闭，不重建空档覆盖玩家资产。

## 第二轮：等级、星级、进化与数值确定性

- 宠物等级严格为 1—60，星级严格为 1—10，羁绊严格为 1—5。
- 升星固定消耗 10、15、20……50 枚灵卵残片，1 星到 10 星合计 270 枚，不使用随机成功率或降星。
- 3、6、9 星分别进入成长体、觉醒体、真形体；10 星显示“真形·圆满”。
- 生命、攻击、防御、灵息、迅捷和战力由物种定位、等级、星级、羁绊确定计算，同一档案重登不会随机漂移。

## 第三轮：账号多人物与并发边界

- 图鉴和材料属于注册账号，当前协战分配属于人物；十职业均可使用同一套系统。
- `pet_lock` 串行保护账号宠物文件，HTTP 的 `pet_`、`wanling_` 与论道命令保持主事件线程执行。
- 同一只宠物不能同时陪伴同账号两个在线人物；离线人物释放后才允许转交。
- 战斗中拒绝暂停、更换、升级、升星、深化羁绊和轮换灵纹，不能靠热切换刷新 PVP 次数或冷却。

## 第四轮：PVE 协战与方士系统隔离

- PVE 只接受同房、同逻辑区、存活的真实 NPC；普通怪、玩家、方士召唤物和跨区对象严格分流。
- 通用灵宠永不克隆 NPC、不登记 `SUMMOND`、不占虎灵/鹤灵/龟灵槽，也不参与三灵共鸣。
- 均衡、轻灵、厚积仍为 30、24、36 秒节奏；满血或满法时也进入冷却并产生零数值陪伴事件，避免逐心跳空转刷屏。
- 伤害不能造成最后一击；恢复遵循现有减疗上限。完整养成最高提供 222% PVE 成长，但仍受目标生命比例硬上限约束。

## 第五轮：人物 PVP 御灵公平性

- 只有双方真实处于同房 PVP 且当前敌对目标归属一致时才充能，任意公开函数调用不能越过战斗态伪触发。
- 轻灵、均衡、厚积分别需要 4、5、6 个有效战斗节拍；每场最多触发两次，换目标不恢复次数。
- PVP 只折算完整培养额外收益的 20%，满培养倍率为 124%；强攻单次最高约为目标生命上限 0.496%，两次合计不足 1%。
- 攻击宠不能补刀；疗愈和灵息宠只作用于主人，事件目标与战斗小窗文案不会误写为敌人。

## 第六轮：快速决胜一致性

- 1000 轮快速决胜读取双方剩余宠物次数、当前目标充能、灵纹节奏与压缩后的 PVP 效果。
- 宠物最多按真实剩余次数加入两次，不随 2/4/8/16 倍模拟加速重复放大。
- 切换对手时旧目标充能按真实战斗规则归零；治疗与伤害双方同时结算，灵息只进入有限终局评分。
- 推演只读临时状态，不改写真实充能、次数、气血、法力或宠物永久档案。

## 第七轮：裂隙、寻迹与材料经济

- 寻迹仍只认真实 NPC 死亡、合适等级和不同死亡对象；召唤物、城战对象和低级碾压不计。
- 裂隙仍要求 3—5 个不同账号、同队、同房、同区玩家，少于三人及时失败，最多 12 轮。
- 裂隙奖励先持久化再领取，场次 ID 幂等；完整灵卵 1% 且 30 场保底，异色 0.1% 且只有外观。
- 灵卵残片同时承担稳定孵化与升星成本，页面明确展示用途；材料始终位于独立栏，不挤人物背包。

## 第八轮：标准化论道与商业边界

- 三宠论道继续使用标准化属性、三局两胜和每局 12 回合；人物等级、装备、VIP及培养数值不进入论道。
- 每日只奖励前三个不同账号对手；同账号多职业不能互刷，重复对手可切磋但不再发奖。
- VIP 不出售宠物属性、升星成功率、PVP次数、裂隙伤害、稀有概率或额外有奖对手。
- 人物 PVP 的有限御灵与标准化宠物论道是两条独立规则，界面和文档均明确区分。

## 第九轮：房间存在感与 Vue 战斗体验

- 其他玩家的随行宠物以非实体文字行显示，不增加房间人数、不成为攻击目标，也不破坏逻辑区不可见过滤。
- 战斗小窗显示等级、星级、进化、战力、PVE 冷却或 PVP 充能及本场次数。
- 协战事件带唯一 ID、PVE/PVP 模式和真实目标；客户端去重后播放一次动画、飘字和日志。
- 手机、平板和桌面共用现有响应式战斗卡；关闭动态效果时仍保留数值与文字反馈。

## 第十轮：全职业创建、发布产物与运行验证

- 使用一次性账号真实走通人类、妖魔、中立全部十职业的“创建人物 → 选角 → `choice_profe` → 进入出生点”HTTP 链路。
- `choice_race`、`choice_profe`、`start` 等初始化命令强制进入主事件线程，避免已有会话或重试时被错误送入并行线程；异常日志保留完整堆栈。
- 宠物专测 44/44、PVP 快速决胜 8/8、整库 TestUnit 51/51、自动卖装高等级装备边界、账号多人物和 HTTP 线程架构均通过。
- Vue 测试与正式构建已同步 `vue_source/dist`、`web/web_vue`；`git diff --check` 通过，最新启动日志没有 Pike 编译错误或 `Attempt to call the NULL-value`。
