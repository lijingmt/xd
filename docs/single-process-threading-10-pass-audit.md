# Xiand HTTP 并发线程十轮审查

审查日期：2026-08-01

目标分支：`codex/noncausal-read-threading`

约束：单 Pike 进程；参考 txpike9 对核心/非核心命令分类，不采用多 Worker。

## 十轮审查

1. **进程模型**：仍只有一份游戏世界和一套存档；HTTP 非核心命令使用进程内线程，不产生第二份房间/NPC状态。
2. **线程数量**：使用 16 线程 `Thread.Farm`，没有 txpike9 旧实现按请求创建 `Thread.Thread` 的无界增长；pending 硬上限 512。
3. **HTTP 事件线程**：主要命令接口入队后立即归还 Backend；Future 完成回调才解析和发送响应，不在 Backend 上 `get()` 等待非核心命令。
4. **因果分类**：战斗、移动、召唤、挂机、交易、地面物品、队伍、副本、家园、社交、跨账号、管理及关服命令保持核心串行；`qge74hye`、`use_toolbar` 等间接移动/战斗入口也已覆盖。
5. **同账号顺序**：同一规范化 userid 永久复用当前存活的互斥锁；同账号请求串行，不同账号非核心请求并行。
6. **人物上下文**：`CONND->this_player` 改为 Pike 9 `Thread.Local`，工作线程和主 Backend 不会覆盖彼此的当前人物；运行测试验证主/子线程分别读回自己的对象。
7. **连接输出**：CONND 连接映射和 HTTP 虚拟连接映射使用短锁；BufferConnection 替换、命令输出和恢复都位于同账号锁范围内。
8. **清理竞态**：空闲连接清理基于锁内快照，并在删除前比较原 `last_used`；请求刚更新过连接时不会被旧快照误踢。
9. **异常与背压**：工作任务、调度失败、Future 失败及回调异常均有计数/日志；线程池满返回 503，pending/active 在成功与失败路径都释放。
10. **兼容与观测**：旧 include 路径只转发唯一实现；`/health` 暴露线程限制、峰值、完成、失败、拒绝和核心/非核心命令计数。

- 三次安全重启后的完整 TestUnit 均为：`passed=40 failed=0 skipped=4`。
- 64 个跨账号并发 `look` 请求：64 个 HTTP 200。
- 同一账号 48 个并发 `score` 请求：48 个响应均返回正确 userid。
- 压测后命令池峰值 pending 14、峰值 active 13；累计完成 113、失败 0、拒绝 0、遗留 pending 0。

- 核心 `save` 请求的核心计数增加 1、并行计数增加 0，证明分类路由运行时生效。
- 最终重启后的 32 路并发冒烟全部成功；线程失败 0、拒绝 0、pending 0。
- `/health`：`status=ok`、容量告警 0、异步 I/O 失败 0、拒绝 0。

## 保留边界

- Pike 纯计算任务不会因为线程自动变快；这次收益主要是避免慢账号请求独占 HTTP Backend，并提高多个互不相关账号的响应并发。
- 直接读战斗状态、房间出口和健康状态的轻量端点仍由 Backend 快速取快照；它们不执行 MUD 命令，也不进入命令池。
- 新增命令若触碰共享对象，必须同步更新核心命令或前缀清单和 TestUnit。
