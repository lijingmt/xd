# Xiand 单进程线程优化十轮审查

审查日期：2026-08-01

目标分支：`codex/isolated-zone-multicore`

约束：单 Pike 进程，不采用 Worker/多进程分片；只线程化与游戏对象隔离的工作。

## 审查结论

1. **进程模型**：生产代码没有 `Thread.Thread` 临时命令线程；人物、房间、战斗、队伍、家园和存档继续共用一个世界状态。
2. **世界单写**：HTTP 命令固定按“账号锁 → 世界锁”执行，并校验调用者必须是 Pike 主 Backend。测试线程调用命令会被拒绝，世界命令计数不变化。
3. **锁与异常路径**：账号锁表、世界锁和指标锁均在异常路径释放；账号锁使用弱值映射，空闲账号不会永久占用映射。
4. **线程池与背压**：Pike 9 `Thread.Farm` 总工作线程上限为 8；读取池 7、日志池 1；读取/日志待处理上限分别为 512/1536，总上限 2048。
5. **I/O 安全边界**：工作线程只接收路径、字符串和整数；路径经过白名单和目录穿越校验，实际读取长度有 8 MiB 硬边界，日志单条有 8 KiB 硬边界。
6. **异步回调与顺序**：静态文件通过 `Concurrent.Future.on_success` 回到主 Backend 后响应；请求对象不进入工作线程。单日志线程保持追加顺序，日志洪峰不阻塞读取池。
7. **心跳公平性**：心跳每片最多 128 个对象并按约 5 ms 预算让出 Backend；对象自己的心跳计数未改变，新增/删除对象在下一轮快照自然收敛。
8. **挂机大房间**：战斗、采集和掉落分别使用 128 对象游标；游标绑定房间，重新开启或换房复位；可见怪跨切片累计。140 个地面对象及换房目标用例通过。
9. **存档与缓存**：人物对象序列化和原子替换仍在世界线程，避免把活对象交给线程；地图、任务、技能和 1–69 级路线使用常驻索引/只读快照，查询返回副本。
10. **运行验证与兼容**：兼容入口只 include 唯一线程管理实现；Pike 9.0.13 连续两次安全重启均为 `passed=40 failed=0 skipped=4`，游戏端口 13800 和 HTTP 端口 8888 均正常。

## 压力与运行态证据

- 本机 100 个纯 Pike 计算任务：顺序约 3.04 秒，线程约 3.30 秒，因此没有线程化 CPU 型游戏逻辑。
- 本机 100 个 20 ms 阻塞任务：顺序约 2.37 秒，线程约 0.035 秒，证明隔离 I/O/等待型任务适合线程池。
- 40 个并发 519 KiB 静态文件请求全部成功；结束后 I/O 指标为 61 个任务完成、0 失败、0 拒绝、0 待处理，峰值待处理 14。
- 最终健康检查：`status=ok`、`capacity_warning=0`、最近心跳周期 21 ms、最大心跳切片 5 ms、存档失败 0。

## 运维边界

`Thread.Farm` 是进程级常驻资源，Pike 9.0.13 没有公开的 Farm 关闭接口。修改 `async_iod.pike` 后必须使用安全保存玩家的完整重启脚本，不能在线 destruct/reload 该守护进程。
