# Xiand 单进程 HTTP 并发与线程管理

## 结论

Xiand 保持一个 Pike 游戏进程和一份共享世界，但不再让所有 HTTP 游戏命令挤在主 Backend 上执行。参考 txpike9 的分类方式，命令分成两类：

- 核心命令：会移动人物、改变战斗/房间/NPC、交易、组队、家园、聊天、管理或跨账号数据，由主 Backend 串行执行。
- 非核心命令：例如 `look`、`score`、`myskills`、`inventory`、`paihang_list`、`use_perform` 等账号内查询或互不依赖的操作，进入有界 `Thread.Farm` 并发执行。

这是一进程多线程模型，不引入 Worker、网关分片或跨进程世界迁移。

## HTTP 命令工作池

- 非核心命令池固定最多 16 条工作线程，最多保留 512 个执行中或排队请求，超限立即返回 503，不允许无限创建线程或无限堆积请求对象。
- `/api`、`/api/html`、`/api/json`、`/api/performs` 和轮询式 `/api/async` 命令队列都使用异步入口。HTTP Backend 只做认证、分类和入队，不会创建线程后原地等待。
- `Concurrent.Future` 完成后回到 Backend 解析 MUD 输出并调用 `response_and_finish`；HTTP Request 对象不会被工作线程直接操作。
- 同一账号固定复用一把命令锁，因此同账号连续点击仍严格按顺序执行，人物输出不会串包；不同账号的非核心命令才并发。
- 核心命令仍校验调用线程必须是主 Backend；工作线程尝试执行核心命令会被拒绝。
- 兼容用的同步入口保留给旧代码，新 HTTP 路由必须优先使用 `execute_command_async`。

## 线程上下文隔离

旧引擎的 `CONND->this_player` 是进程级单变量，不适合并发命令。现在使用 Pike 9 `Thread.Local`：每条线程拥有独立的 `this_player`，主 Backend、不同账号工作线程之间不会互相覆盖。

连接映射和 HTTP 虚拟连接映射使用短时互斥锁保护。空闲连接清理先复制快照，再以 `last_used` 比较并认领超时连接，避免清理线程把刚刚活跃的账号踢下线。玩家命令执行期间的临时 BufferConnection 仍受同账号命令锁保护。

## 核心分类维护规则

核心命令表覆盖战斗、移动、召唤、挂机循环、购买交易、地面物品、仓库、队伍、副本、帮派、师徒、聊天、家园、邮件、管理命令和关服命令。共享子系统还使用前缀兜底，例如 `term_`、`fb_`、`bang_`、`home_`、`mail_`、`chatroom_`、`city_`、`lottery_`、`vip_`、`yushi_`、`mgr_` 和 `wiz_`。

新增命令时按以下顺序判断：

1. 是否改变其他玩家、房间、NPC、掉落、队伍或全服守护进程；若是，必须核心化。
2. 是否可能间接调用移动、战斗、交易、聊天或管理命令；若是，必须核心化。
3. 是否只访问本账号数据，且同账号锁足以维持顺序；若是，可并行。
4. 无法确认时先列入核心命令，验证后再放开。

## 独立 I/O 线程池

文件 I/O 继续由 `async_iod.pike` 处理：读取池 7 条线程、顺序日志池 1 条线程，总待处理上限 2048。静态文件异步读取，离线认证/config 读取使用有界 Future，非关键日志单线程顺序追加。该池与命令池分离，日志洪峰不会占满命令线程。

## 心跳与挂机预算

- 全局心跳每片最多处理 128 个对象，并在约 5ms 后让出 Backend。
- 挂机战斗、采集和掉落使用 128 对象轮转扫描，游标绑定房间，换房或重开挂机后复位。
- 地图、任务、技能和练级路线继续使用常驻索引/只读快照。

## 运行监控

`/health` 的 `threads` 字段提供工作线程上限、待处理上限、当前/峰值 pending、当前/峰值 active、完成、失败、拒绝、核心命令数和非核心命令数。`async_io`、心跳、Backend 延迟、CPU 与存档指标继续保留。

## 验证方法

- `test_http_thread_architecture.pike`：验证核心分类、16/512 背压、异步路由、同账号锁、核心 Backend 门禁、`Thread.Local` 和连接表锁。
- `test_single_process_runtime_optimization.pike`：验证命令/I/O Thread.Farm、心跳预算、存档和缓存。
- 本地并发验证同时覆盖跨账号请求和同账号突发请求，并检查响应账号、HTTP 状态及线程池完成/失败/拒绝计数。

两个 `Thread.Farm` 都是进程级常驻资源；修改线程池或 `Thread.Local` 后必须使用安全保存玩家的完整重启脚本，不能在线热卸载守护进程。
