# 每日限时原创玩法设计与运维说明

## 目标

本模块增加两个相互独立的每日玩法，补充“升级之外”的短时、高参与度内容。二者只共享配置、逻辑区隔离、资格、奖励幂等和故障恢复基础设施，不共享核心玩法。

- **天衡绝境（PVP）**：随机镜域 1v1 生存赛。
- **九曜镇渊（PVE）**：九宫封脉、路线控制与巡游首领协作战。

名称、世界观、战势、镜域配对、曜脉封锁和巡游首领均为本项目重新设计；没有沿用玩家提案的活动名称，也没有照搬“同图移动即自由混战”或“固定九宫格站桩首领”的实现。

## 天衡绝境

每日中国时间 20:00 开始集结，入口开放十分钟。战斗开始后不能中途加入。

参赛者在天衡台选择任意方向移动后进入随机队列。配对成功时，双方被送进只属于该场对局的镜域，其他玩家不能进入，因此从结构上消除了围攻、堵门和主观合围。三种战势只提供小幅局内策略，不改变角色永久数值：

- **锋势**：入场压制对手 2% 气血上限；守势会将其减半。
- **守势**：每轮入场恢复 4% 气血，适合连续作战。
- **变势**：入场恢复仙力，胜出后恢复少量气血与仙力。

一次落败、主动认输或断线超过宽限时间即被淘汰，当日不能重新入场。淘汰时以“淘汰后剩余人数 + 1”确定名次，最后存活者为第一名。消极不移动者会在可配置时限后自动进入随机配对，普通 PK 的 90 回合快速决胜仍负责处理极端长局。

## 九曜镇渊

每日中国时间 21:00 开始集结，入口开放十分钟。玩家从九曜心出发，巡渊主从外围阵位进入并按未封闭的曜脉随机巡游。

每个阵位可以协力封脉。存活人数少于四人时单人可完成，四人及以上需要两名不同玩家响应。封脉具有三个结果：

1. 暂时阻止首领和渊将进入该阵位；
2. 对巡渊主造成 2% 气血上限的阵纹反噬；
3. 当首领所有相邻路线均被封闭时，继续受到围困反噬。

沉山、燎空、断潮、蚀月四名渊将在战局的四个阶段依次出现。玩家击碎巡渊主核心则成功；所有玩家被击败或时间耗尽则失败。首领和渊将会在与玩家同房且未交战时主动攻击，不是被动木桩。

## 公平性与奖励

两个玩法均不出售战斗属性、奖励倍率、额外入场次数或复活机会。VIP 与普通玩家使用相同规则。奖励只包含经验、金币和两个玩法各自的活动令牌；普通怪物经验、任务进度和掉落链在活动 NPC 死亡时被明确跳过，避免重复奖励。

奖励先写入活动状态，再发放到人物并标记已领取。断线玩家下次登录时会领取未发奖励，同一奖励不会重复发放。

## 隔离、安全与故障处理

- 每个活动场次按 `event + date + logical-zone-group` 建立，隔离区玩家在房间、战斗、排名和奖励上都不会相遇。
- 活动房间没有普通出口，并拦截飞行、传送、跟随和管理外的普通移动；活动守护进程使用一次性内部移动标记。
- 玩家死亡在职业自动复活、宠物复活、掉级、耐久、荣誉和普通复活之前由活动状态机接管。
- 活动 NPC 死亡在普通经验、任务和掉落之前接管，防止双重结算。
- 活动克隆房间不写入 `last_pos`，重新登录由活动状态恢复到权威场次。
- 集结期重启可继续集结；战斗期重启会安全取消本场，玩家不承受死亡惩罚，并获得一枚纪念令。这样不需要恢复不完整的 NPC 气血或战斗快照，避免重启复制奖励。
- 活动状态使用 JSON 临时文件、备份文件和原子替换保存，损坏或超大文件会失败关闭。

## 配置与部署

配置文件为 `gamelib/etc/timed_events.json`，包括时区偏移、开放时间、集结/战斗时长、最低等级、最低人数、断线宽限、强制配对、封脉持续时间和首领移动间隔。默认时区为 UTC+8，不依赖生产容器的本地时区。

代码和配置都位于现有 `gamelib` 部署目录内，不需要预建数据目录。第一次启动时会自动创建 `data_xiand/timed_events/`，运行数据不应提交 Git。

## 验证

`test_unit/test_timed_event_system.pike` 覆盖真实 Pike 编译、UTC+8 时间窗、九宫边界、封脉人数、排名公式、原创命名、传送拦截、动态首领和完整生命周期接线。Vue 侧 `vue_source/tests/timed-event-ui.test.js` 覆盖状态轮询、单场去重、弹窗动作、快捷入口、动态视口和减少动画偏好。
